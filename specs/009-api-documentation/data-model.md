# Phase 1 Data Model: API Documentation via OpenAPI/Swagger

This feature introduces no new persisted (database) entities. It introduces two build/serving
artifacts, documented here in place of a traditional data model.

## OpenAPI Document

The machine-readable contract artifact, generated by `swag init` from Go doc-comment
annotations.

| Field | Type | Notes |
|-------|------|-------|
| `info.title` / `info.version` | string | Sourced from `@title`/`@version` annotations in `backend/cmd/api/docs.go` |
| `basePath` | string | `/api/v1`, matching `docs/api-design-standards.md` versioning convention |
| `paths` | map | One entry per annotated handler; path, method, parameters, request body schema, response schemas per status code |
| `definitions` | map | Derived from Go request/response struct field tags (`json:"..."`, validation tags) — Swagger 2.0's flat schema-registry field (OpenAPI v3's `components.schemas` does not apply here) |
| `securityDefinitions.BearerAuth` | object | `type: apiKey`, `in: header`, `name: Authorization` — declared once in `docs.go`, referenced per-endpoint via `@Security BearerAuth` (Swagger 2.0's top-level `securityDefinitions`, not v3's `components.securitySchemes`) |

**Generation rule**: A handler function appears in `paths` if and only if it carries `swag`
annotations (`@Summary`, `@Router`, etc.). This is the sole exclusion mechanism (see
`research.md`) — no separate allow/deny-list entity exists.

**Lifecycle**: Regenerated by `make swagger` whenever an annotated handler changes; committed to
`backend/docs/`; verified for drift by CI (`git diff --exit-code`) on every pull request
touching `backend/`.

## Documentation UI (Swagger UI)

Not a data entity — a stateless rendering of the OpenAPI Document above, served by
`swaggo/http-swagger`. Has no persisted state of its own; any credentials a user supplies
in the UI (e.g., a bearer token, once Sprint 5 auth exists) are held client-side in the browser
for the duration of the page session only, exactly as they would be for a manual `curl`/Postman
request — the UI does not store or log them server-side.

## Relationship

```
Go handler + doc-comment annotations
        │  (swag init)
        ▼
OpenAPI Document (backend/docs/swagger.json, swagger.yaml, docs.go)
        │  (http-swagger.Handler)
        ▼
Documentation UI (served at /swagger/*)
```
