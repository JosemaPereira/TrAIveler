# Implementation Plan: API Documentation via OpenAPI/Swagger

**Branch**: `009-api-documentation` | **Date**: 2026-07-10 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/009-api-documentation/spec.md`

## Summary

Generate a machine-readable OpenAPI v3 contract directly from Go doc-comment annotations
colocated with each backend handler (`swaggo/swag`), and serve it through Swagger UI
(`swaggo/http-swagger`) so contributors and API consumers can browse and execute real
requests against a running backend instead of relying on hand-written Markdown. A CI check
regenerates the contract and fails the PR if it differs from the version committed to the
repo, closing the drift gap that motivated this feature. Swagger UI is reachable in every
environment, mounted so it automatically inherits whatever authentication middleware guards
`/api/v1` — no bespoke auth is invented ahead of the Sprint 5 auth work.

## Technical Context

**Language/Version**: Go 1.26 (per `backend/go.mod`; satisfies the constitution's Go 1.24+ floor)

**Primary Dependencies**: `github.com/swaggo/swag` (CLI + annotation parser, generates the
OpenAPI artifact), `github.com/swaggo/http-swagger/v2` (Chi-compatible Swagger UI handler),
`github.com/swaggo/files` (embedded Swagger UI static assets, pulled in transitively by
`http-swagger`)

**Storage**: N/A — no new persistent storage; the generated contract is a build artifact
committed alongside code, like generated protobuf/mock code elsewhere in this repo

**Testing**: Go `testing` + `testify` (existing); a new integration test asserting
`/swagger/doc.json` parses as valid OpenAPI v3 and `/swagger/index.html` returns 200; CI
drift-check step (regenerate + `git diff --exit-code`) is validation, not a unit test

**Target Platform**: Linux server (ECS Fargate, ARM64) — same runtime as today, no new
infrastructure

**Project Type**: Web service (backend-only addition to the existing Go/Chi monorepo backend)

**Performance Goals**: N/A — contract generation is a build/CI-time step, not a request-path
operation; Swagger UI asset serving has no meaningful latency budget beyond normal static-file
serving

**Constraints**: Contract generation MUST NOT materially slow `go build`/CI (informed by the
prior QEMU/Docker cross-compilation perf work — see `patterns-discovered.md`); the CI
drift-check MUST run on every PR touching `backend/` and MUST be addable as a required status
check per the existing ruleset pattern (`dorny/paths-filter` gate, always-running per
`patterns-discovered.md`'s "Required Status Checks Must Always Run")

**Scale/Scope**: Single backend service; today only `/healthz` (intentionally undocumented)
and the throwaway `internal/example` CRUD demo exist as routes — the contract starts small
and grows automatically as real domain handlers (Sprint 5+) add their own annotations

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **I. Test-First Development**: The new integration test (`swagger.json` validity + `/swagger/index.html` 200 OK) is written before the route is wired (Red → Green). The CI drift-check is a validation gate, not a substitute for tests, and is documented as such in `docs/testing-guidelines.md` alongside the existing gates. **PASS**.
- **II. Simplicity — KISS & DRY**: Reuses the existing `swaggo` ecosystem (the de facto standard for Go) instead of a bespoke generator; no new abstraction layer — the generated `docs` package is consumed directly by one `http-swagger` handler mount. **PASS**.
- **III. Code Quality & Consistency**: Generated code (`backend/docs/docs.go`) is machine-generated and MUST be excluded from `golangci-lint`/`gofmt` manual-authorship rules via a generated-file marker (`// Code generated by swag ...  DO NOT EDIT.`, which `golangci-lint` already recognizes and skips by default) — no constitution amendment needed. **PASS**.
- **IV. Accessible & Token-Driven UI**: Not applicable — Swagger UI is a third-party vendored UI (not a project component built from design tokens); it is a developer/API-consumer tool, not an end-user-facing surface subject to the project's own design system. **PASS (N/A)**.
- **V. Secure Configuration**: No secrets are introduced. The Swagger UI mount point is wired to inherit the same auth middleware chain as `/api/v1` (no parallel auth mechanism); until that middleware exists (pre–Sprint 5), the mount carries a `// TODO(sprint-5): wire real auth middleware here` marker rather than inventing interim credentials. **PASS**.
